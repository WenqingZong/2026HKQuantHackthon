# 2026 HK Quant Hackathon — ETF 因子与机器学习流水线

这是队伍里 **zwq 负责的模型部分**：从 Databento 拉原始行情 → 计算 Alpha101 + Alpha158 因子 →
训练 MLP / XGBoost / LightGBM → 用 Rank IC 和 top-k 等权回测评估。

行情用各交易所自己的数据集拼出 2018-05 起的日线（比合并行情多 5 年），因子是 psq 相关性分析
去重之后的 186 个。改 `config/default.yaml` 里的 `dataset.alphas` 就能换因子，模型代码不用动。

## 快速开始

```powershell
uv sync                     # 装依赖（torch 走 pytorch-cu130 源，5090 可以直接用）
```

Databento 的 key 放在仓库根目录的 `.env` 里（这个文件不进 git）：

```
DATABENTO_API_KEY=db-xxxxxxxx
```

然后按顺序跑：

```powershell
uv run python main.py download   # 各交易所原始数据（已下载的文件直接复用，不重复扣费）-> 拼日线
uv run python main.py features   # 算 186 个因子、生成数据集，约 1 分钟
uv run python main.py train      # 训练三个模型并评估；树模型几分钟，MLP 在 CPU 上较慢
uv run python main.py all        # 上面三步一起跑
```

单独跑某个模型、换配置文件：

```powershell
uv run python main.py --config config/default.yaml train --models xgboost
```

提交前的检查：

```powershell
uv run python -m pytest tests -q
uv run ruff check . ; uv run ruff format --check .
uv run mypy
```

## 数据

### 数据源怎么选的

比赛给的是 Databento 历史数据接口。几种日频来源的差别：

| 来源 | 起始日期 | 说明 |
| --- | --- | --- |
| `EQUS.SUMMARY` | 2024-07-01 | 官方合并日线，成交量是全市场的；历史最短 |
| `EQUS.MINI` | 2023-03-28 | 价格是合并行情，成交量只含部分场所（约 3–8%，比例会漂移） |
| **各交易所数据集（当前）** | 2018-05-01 | NYSE Arca / Nasdaq / Cboe BZX / Cboe EDGX / NYSE 各自的行情，自己拼成日线 |

当前用第三种（`data.venues` 非空时启用，见 `hkq/venues.py`），历史比 SUMMARY 长 6 年多。拼接口径：

- **开盘 / 收盘**：上市交易所的官方开盘、收盘竞价价（`statistics` 里 stat_type 1 / 11），
  多家都发布时取竞价成交量最大的那家。竞价价缺失（约 3%，多在 2018–2021 年）时用 09:00 / 15:00
  那根小时线里最活跃交易所的开 / 收价。
- **最高 / 最低**：各交易所小时线在纽约时间 09:00–15:59 的极值（日线含盘前盘后，会把极值拉偏）。
- **成交量**：各交易所显性成交之和，约为合并成交量的 40%，比例逐年稳定（0.44 → 0.43）。
  比率类、相关系数类因子对这个整体缩放不敏感；跨标的的成交额排名和真实值的 Spearman 约 0.97。
- **ticker 复用 / 换策略**：按 `selected_etfs/*_universe.csv` 的 `history_start_date` 与
  `inception_date`（取较晚者）裁掉之前的行情。例如 IBIT 在 2024-01 之前是另一只证券，VNM 2023-03 换了策略。

在 2024-07 之后和官方 `EQUS.SUMMARY` 逐行对比（约 10 万行）：

| 字段 | 偏差 > 5bp 的比例 | 偏差 > 1% 的比例 |
| --- | --- | --- |
| open | 7.7% | 0.05% |
| high | 17.7% | 0.59% |
| low | 15.2% | 0.28% |
| close | 2.0% | 0.009% |

收盘到收盘的日收益和官方数据相比，99% 分位误差 18bp。最高/最低偏差大一些，是因为交易所数据里
没有场外（TRF）成交，影响的只有用到极值的因子。

想换回单个数据集：把 `data.venues` 置空，`data.dataset` / `data.start` 改成对应的值。
`data/raw/bars_daily.EQUS.SUMMARY.parquet` 留着一份官方合并日线，用来做上面这种核对。

### 下载了什么

- 代码池 = 训练池（`training_tickers.csv`，172 只）∪ 交易池（`trading_tickers.csv`，176 只）= **182 只**；
  训练用的是全部 182 只（有足够历史的那部分）。
- 每个交易所三类原始文件放在 `data/raw/venues/`：日线、小时线、开收盘竞价价。

- 合成后的日线落在 `data/raw/bars_daily.parquet`，`bars_daily.manifest.json` 记录每个兜底环节用了多少行。

### 分红与拆股（复权）

Databento 给的是**未经复权的原始成交价**：除息日价格会自然下跌，拆股日价格按比例缩水。
不复权的话，标签会把分红当成亏损，拆股更会变成一根 -67% 的假 K 线
（SCHD 2024-10 拆股那天原始价格从 84.62 掉到 28.54）。

分红与拆股记录来自 yfinance（`data/raw/venues/corporate_actions.parquet`，2018 年起，约 6000 次派息、28 次拆股）。
`hkq/corporate_actions.py` 据此算复权因子：`复权价 = 原始价 × f`，事件日满足
`f_t / f_{t-1} = 拆股比例 + 每股分红 / 收盘价`，这样 `adj_t / adj_{t-1} - 1` 就是含分红再投资的
真实收益。成交量按拆股因子倒数调整，保持「量 × 价」不变。

两个要点：

- **复权因子是因果的**：只用当日及之前的事件，不做「除以最后一天」的后复权。后复权会让 t 日的价格
  水平依赖 t 之后的分红和拆股，是未来函数。代价是拆过股的标的，价格水平和没拆过的差一个固定倍数，
  对收益率、比率类因子没有影响。`tests/test_leakage.py` 有一条回归测试：在 cut 之后补一次拆股，
  cut 之前的特征和标签必须一字不差。
- **yfinance 的分红被追溯调整过**：拆股之前的分红会按之后的拆股比例缩小
  （SCHD 拆 3:1 之前每季派约 0.75 美元，yfinance 给 0.25）。如果直接拿去除以当时的原始收盘价，
  拆股前的股息率会被低估成 1/3。`load_actions` 读入时乘回除息日之后所有拆股比例，
  还原当时实际派的金额。这一步只是还原当时已公开的数字，不引入未来信息。

复权后单日涨跌仍超过 35% 的会打一条 warning。目前剩 3 条，都是真实行情：
XOP 2020-03-09 油价崩盘、KWEB 2022-03-16 中概反弹、MSOS 2025-12-12。

## 因子

一共 **186 个**：78 个 Alpha101（`hkq/alphas.py`）+ 111 个 Alpha158（`hkq/alpha158.py`），
减去 3 组重复各去掉一个（`alpha033≡-KMID`、`alpha101≡KMID2`、`alpha054≡-KSFT2`，保留 Alpha101 那一侧）。

- Alpha101 全部 78 个都实现了；需要 vwap 的用 **HLC3 代理**、需要 advN 的用 **N 日平均美元成交额**，
  和 psq 相关性包的口径一致；原文里的分数窗口（如 12.7054）取整。
- Alpha158 按 Qlib 定义实现（9 个 K 线形态 + 4 个价格位置 + 5/10/20/30/60 五个窗口的滚动统计），
  只注册 psq 那份相关性包里实际出现的 111 个列名。这 111 个之间 |ρ| ≥ 0.9 的只有 2 对，
  说明子集已经预先去过重。
- **缺失值必须保持缺失**：NaN 参与比较的结果是 False，三元因子（`x < y ? 1 : -1`）、min/max、
  布尔计数（CNTP/CNTN）如果不处理，会在预热期和未上市的日子输出确定的 ±1 或 0，看起来就像信号。
  `alphas.py` 的 `_if_less` / `_min` / `_max` 在任一输入缺失时结果也缺失。
  `build_dataset` 还会把当天没有行情的标的的所有因子置空，避免它们参与横截面排名。
  `tests/test_leakage.py` 覆盖了全部 186 个因子：不偷看未来，也不在上市之前给出数值。

## 数据集

`hkq/dataset.py` 把宽表拼成 `(date, symbol)` 的长表，每一步都有明确的时间约束：

1. **标签**：`lag=1`、`horizon=5`。因子用当日收盘价算，最早只能下一个交易日成交，
   所以标签是「第 t+1 日收盘进场、持有 5 个交易日」的收益。不做这个滞后等于自带前视偏差。
2. **标签标准化**：默认按日做横截面 `rank`。一是把回归变成排序，和「选前 k 只」的目标一致；
   二是去掉市场整体涨跌（beta），模型不用花容量去拟合「今天大盘涨不涨」。
   这是纯单调变换，不影响 Rank IC 的数值。
3. **因子标准化**：同样按日做横截面 `rank`，映射到 `[-0.5, 0.5]`，缺失值填 0（中性）。
   树模型和 MLP 都不用再套 scaler，也不会有跨期泄漏。
4. **预热期 `min_history = 250`**：不能短于任何因子的回看（最长的是 alpha019/039 的
   `sum(returns, 250)`），否则训练集开头会是「半截因子 + 填 0」的样本，和测试集分布不一致。
   `build_dataset` 会实测每个因子的预热天数，超过 `min_history` 就直接报错。
   预热按标的各自计算：晚上市的 ETF 也要攒够 250 根 K 线才进入数据集（2025 年后上市的 7 只因此暂不参与）。
5. **切分**：train 2019-05 ~ 2022-12、valid 2023、test 2024-01 ~ 2026-10，严格按时间先后，不交叉。
   切分边界没有 purge（训练集最后 6 天的标签会用到验证期的价格），影响很小；
   `scripts/walk_forward.py` 里做了 purge。

## 模型

三个模型对外只有 `fit(X, y, X_valid, y_valid)` 和 `predict(X)` 两个方法，
在 `hkq/models.py` 的 `build_model` 里注册：

- **XGBoost / LightGBM**：回归未来收益，验证集早停。
- **MLP**：PyTorch，层宽、Dropout 在 config 里配，AdamW，验证集损失早停，有 CUDA 就用 GPU。
- **线程数**：这台 WSL 上树模型和 torch 用满全部核会慢 5–20 倍（线程争用），
  config 里的 `n_jobs`（树模型）/ `threads`（MLP）设成 8。

加第四个模型（比如 LightGBM 的排序目标、或者 LSTM）只要实现这两个方法，再在
`build_model` 里加一行分支。

> 早停说明：标签噪声很大（5 日收益的信噪比本来就低），所以 MSE 早停在几十棵树的量级就停了。
> 换成 `label_norm: rank` 之后明显改善（XGBoost 35 棵 vs 5 棵，预测值也不再挤成几个值）。
> 想继续调就动 `models.*` 的参数和 `train.early_stopping_rounds`。

## 评估

- **Rank IC**：每个交易日算一次预测值与未来收益的 Spearman 相关，再看均值、ICIR、
  胜率、t 值。这是判断"模型有没有选股能力"最直接的指标。
  注意报告里的 `ic_t = ICIR × √天数` 把逐日 IC 当成独立样本，但 5 日标签是重叠的，
  相邻几天的 IC 高度相关，这个 t 大约高估 √5 倍；看显著性要用 Newey-West 或每 5 天取一个点。
- **top-k 回测**：逐日盯市的组合模拟。信号日 t 出预测，第 t+1 个交易日收盘成交（和标签的
  `label_lag` 对齐）；建仓时等权买入前 10 只，之后**只有进出的标的才交易**，留在组合里的
  标的权重随涨跌自然漂移、不重新等权。基准是期初等权买入全池后不再调仓、不计成本。
  同分的股票会先随机打散，避免默认按代码字母序选股。
- 每次训练还会输出**逐因子**的 Rank IC 表（`artifacts/alpha_ic.csv`），
  后面 psq 做因子筛选、以及看哪类因子在这个池子里真正有效时可以直接用。

**交易成本**：账户佣金实测约 0.4–0.7 bp/边，加上滑点，`backtest.cost_bps` 先设 **1.5 bp**。
计提方式是 `net = (1 + gross) × (1 − Σ|Δw| × bps / 1e4) − 1`：

- `Σ|Δw|` 是当期成交的**名义金额**，卖出和买入都算进去，所以乘的是一个单边费率；
  空仓建仓只成交一次 100%，不会把现金的变化重复计一遍。
- 换手按 `0.5 × Σ|Δw|` 报告（当前约 0.8/次），年化拖累约 1.5%。
- 报告里附**成本敏感度表**（默认成本的 0/1/2/4/8 倍，即 0 / 1.5 / 3 / 6 / 12 bp），可以直接看出策略能承受多高的摩擦。
- 口径上的偏差：所有 ETF 统一用同一个费率，而池子里 FXF / FXB / CMBS 这类
  日均成交额只有 200–400 万美元的标的，1.5 bp 明显偏乐观；基准是**不计成本**的。

## 当前结果

数据 2018-05 ~ 2026-10（交易所拼接日线 + 分红拆股复权），186 个因子，训练 2019-05 ~ 2022-12（926 天）、
验证 2023（250 天）、测试 2024-01 ~ 2026-10（703 天）。成本单边 1.5bp，基准是全池等权买入持有（不计成本）。

### 怎么选的

`scripts/sweep_models.py` 把**因子集也当成超参**：全部 186 个、只用 Alpha101、只用 Alpha158、
按训练集 |ICIR| 排序并以 |ρ|<0.8 去重后的全部 154 个（dedup）/ 前 100 / 60 / 30 / 15 个。
因子子集只用训练集构造；树模型 8 个因子集 × 每种 4 组超参（64 次），MLP 6 组超参 × 5 个因子集
再加最初 2 次高学习率的（32 次），共 96 次训练。结果在 `artifacts/sweep/`。
**每个模型只按验证集 ICIR 选**，测试集的数字写进表里，但不参与选择。

- 验证集 ICIR 和测试集 ICIR 的相关系数：树模型 0.60、MLP 0.70，按 ICIR 选是有效的；
  验证集回测 Sharpe 和测试集回测 Sharpe 的相关系数是 **-0.31**，按回测收益选配置等于在选噪声。
- 两族合用明显好于单族：只用 Alpha101 或只用 Alpha158 的验证/测试 ICIR 都最低。
  树模型在 all / dedup 上最好；MLP 反而是前 30 个因子最好。
- MLP 用验证集 MSE 早停时，最优点几乎都在第 1 个 epoch（IC 0.03 对应的 R² 只有 0.001 量级，MSE 看不出好坏）。
  改成按验证集相关系数早停（`stop_on: corr`）、网络缩到 64 宽之后才和树模型可比。
  原先的 [2048, 1024, 512] 测试集 IC 0.040。

| 模型（因子集） | 验证 ICIR | 测试 IC | NW t | 年化 | Sharpe | 最大回撤 | β | 扣 β 后 alpha（t） |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| XGBoost depth 7（all） | 0.204 | 0.048 | 3.4 | 26.8% | 1.36 | -16.6% | 1.27 | +7.8%（1.5） |
| LightGBM 255 leaves（dedup） | 0.190 | 0.053 | 3.6 | 15.3% | 0.86 | -21.1% | 1.25 | -1.5%（-0.3） |

| 前 2 名等权集成（按验证集选 K=2） | 0.206 | 0.052 | 3.5 | 23.3% | 1.21 | -18.0% | 1.27 | +5.0%（0.9） |

XGBoost 26.8% / LightGBM 19.1% / MLP 17.5%。

### 这些数字该怎么读

- **排序能力是真的**：三个模型测试集 IC 0.048–0.057，Newey-West t 都在 3.4 以上，
  每 5 天取一个点（标签不重叠）t 也有 2.6–2.9。
- **年化收益大部分是 beta，不是选股**：持仓里股票占 84–91%（池子里 70%），债券 1–4%（池子 18%），
  组合 β≈1.25。对基准回归之后，alpha 只有 XGBoost 那组勉强为正（t=1.5），其他都不显著。
- **单个波动率因子就能拿到差不多的 IC**：STD20 一个因子测试集 IC 0.051（模型 0.048–0.057），
  模型里 XGBoost 最重要的特征也是 STD20 / KLEN / STD10 / STD60。剔除波动率之后模型的 IC 还剩
  0.031–0.034（t≈3.2），股票内部的 IC 约 0.02（t≈2.2）——有残余信号，但比总 IC 小得多。
- **年化本身噪声很大**：两族合用的 48 组树模型配置测试集 IC 都在 0.046–0.062，年化却从 12.7% 到 35.1%；
  200 个随机挑 10 只（同样规则、同样成本）的组合，年化中位数 13.7%、5%–95% 区间 7.2%–20.5%。
- **单因子基线**：训练集 |ICIR| 最高的 CORD60 单独用，测试集年化 18.6%、Sharpe 1.13、换手只有 0.30。
- **多空价差也主要是 beta**：做多前 10、做空后 10，空头腿多是债券和防御型标的，价差对基准的 β 0.7–1.0，
  扣 β 后 alpha 的 t 只有 0.3–1.5。

### 逐年滚动重训（`scripts/walk_forward.py`）

每年用之前全部数据重训、前一年早停，训练/验证末尾各 purge 6 天：

| | 2022 | 2023 | 2024 | 2025 | 2026* | 全区间 |
| --- | --- | --- | --- | --- | --- | --- |
| XGBoost depth 7（all）IC | 0.041 | 0.040 | 0.055 | 0.069 | 0.033 | 0.048 |
| XGBoost 年化 | -18.4% | 14.0% | 25.2% | 20.9% | 3.7% | **8.0%** |
| 基准年化 | -10.6% | 11.9% | 8.1% | 22.7% | 13.0% | **8.2%** |

*2026 截至 10 月。IC 每一年都是正的，但只做多前 10 只的组合在 4.8 年里**没有跑赢**全池等权：
2022 年熊市里高 beta 持仓多亏 8 个点，2026 年又落后 9 个点。LightGBM（dedup）和 MLP（top30）从 2024 年起
（因子子集用到了 2022 年之前的数据、配置是在 2023 年挑的，所以只有 2024 年之后是干净的）：
年化 17.3% / 19.1%，同期基准 14.0%，两者 2026 年都跑输基准。

**结论**：模型确实有稳定、显著的横截面排序能力（IC≈0.05），但「全池 rank 标签 + 只做多前 10 只」
这套组合构造把它主要变成了一个高 beta 倾斜：牛市里年化 15%–27%，熊市里跑输，扣掉 beta 之后的超额不显著。
在这个基础上继续调超参意义不大，下一步的重点是标签和组合构造（见下面第 1 条）。

## 已知限制 / 下一步

1. **标签里混着 beta**：标签是全池横截面 rank，牛市里高波动、高 beta 的标的天然排在前面，
   模型很大一部分 IC 来自「挑高波动」（单个 STD20 因子的测试集 IC 就有 0.051）。只做多前 10 只的组合
   β≈1.27，walk-forward 里 2022 年熊市跑输基准 8 个点。要不要换成去 beta / 按资产类别内部排序的标签、
   或者用 beta 中性的组合构造，需要团队来定。
2. **top-10 组合的年化噪声很大**：IC 几乎一样的配置（0.046–0.062），测试集年化可以从 13% 到 35%。比较模型请看 IC / ICIR
   和 Newey-West t，不要看单次回测的年化。报告里的 `ic_t` 没有考虑 5 日标签重叠，大约高估 √5 倍。
3. **测试集已经被看过**：2024-01 之后的数据在这一轮里只读了一次（选择全在验证集上），但之前几轮
   （EQUS.MINI / SUMMARY）的测试窗口落在这个区间内，严格的样本外只剩下之后的新数据。
4. **持仓重叠**：ETF 池去重后仍会有重叠暴露，可以按 `overlap_family` 做组内约束，或者在组合层面限制单方向权重。
5. **风控没接**：回测里只有交易成本，没有止损、波动率目标、仓位上限，这部分要等 zy 的方案。
6. **执行假设**：按收盘价全额成交，没有冲击成本和部分成交；所有 ETF 统一 1.5bp，
   对 FXF / FXB / CMBS 这类日均成交额只有几百万美元的标的偏乐观。
7. **换手高**：每 5 天换掉约 80% 的持仓，年化成本拖累约 1.3–1.5%；要降换手得从信号端入手
   （拉长 horizon、换手惩罚、持仓缓冲带）。
8. **分红/拆股依赖 yfinance**：非官方接口、经常限流。现在的表已经存好，`download` 不会覆盖；
   刷新要先删文件。复权后的异常跳空会打 warning，真实交易前要人工核对。
9. **交易所拼接日线的局限**：没有场外（TRF）成交，最高/最低和官方合并行情的偏差比收盘大；
   成交量只有显性成交（约 40%）。`splits_from_price_jumps` 这个兜底函数目前没有被调用，也没有测试。
